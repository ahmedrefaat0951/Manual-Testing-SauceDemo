# SauceDemo Test Plan

## Objective

The objective of this test plan is to define the scope, approach, and activities for manually testing the SauceDemo web application. The testing aims to verify that the application's core functionality and user interface behave as expected, identify defects, and document test results using professional QA practices.

## Scope

### Application Areas

- Login
- Inventory / Products
- Cart
- Checkout

### Supporting Functionality

- Menu Navigation
- Logout
- Navigation between the main application areas

### Testing Types

- Functional testing
- UI testing
- Positive testing
- Negative testing
- Exploratory testing

### Out of Scope

- External websites/pages such as About
- Performance testing
- Security/penetration testing

## Approach

Testing will be performed manually using a web browser. The testing approach will include functional, UI, positive, negative, and exploratory testing. Test cases will be executed against the defined application areas, with actual results compared against expected results. Identified defects will be documented using bug reports and supported with screenshots where appropriate.

## Test Environment

**Application:** SauceDemo Web Application

**Operating System:** Windows 10

**Browser:** Google Chrome (version varies by test execution date)

**Test Accounts:** SauceDemo provides predefined test accounts. Test accounts will be selected based on the functionality being tested.

## Test Deliverables

- Test Plan
- Test Cases
- Bug Reports
- Screenshots

## Entry Criteria

- SauceDemo is accessible through a web browser.
- The application features within the defined scope are accessible for testing.

## Exit Criteria

- All planned test cases within the defined scope have been executed.
- Test results have been documented.
- Identified defects have been documented in bug reports.
- Relevant screenshots or other supporting evidence have been collected where appropriate.

## Risks and Assumptions

### Risks

- SauceDemo may become temporarily unavailable, preventing test execution.
- Application behavior may change without notice, which could affect previously recorded test results.

### Assumptions

- Expected behavior will be determined from the application's available information and observable behavior where formal requirements are not provided.
- The provided SauceDemo test accounts are available for use when required by the functionality being tested.
